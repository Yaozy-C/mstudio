# Environment and scene reference assets

Use for reusable locations, set layout, spatial anchors and designed light states. Preserve the selected project art direction and use the shared [visual quality method](visual-quality.md). A location asset defines the visual setting that later camera views inhabit; it is not an unrelated attractive background for every shot.

## Establish a location baseline

Read the selected scene design and actual consuming shots. Reuse suitable existing location references. If a location is missing, establish one useful baseline image showing the main surfaces, landmarks, working area and depth relationships. An empty environment can help later placement, but do not remove people or set dressing that are part of the selected reference without a reason. Generate only needed views, not a mandatory environment pack.

Retain the facts that make this one place: ground or floor, boundaries, openings, horizon, major structures, relative scale and fixed set pieces. Store necessary relationships in existing asset/shot text and reference purposes. A proposed layout is a design choice; do not present it as a measured floor plan or a recovered fact about an unseen location.

## Separate layout, look and light state

Use a scene image for its declared environment and spatial evidence. A selected look image supplies palette, rendering medium and material treatment. A composition sketch or layout reference supplies arrangement, viewpoint or gaze/placement guidance. One image can serve several roles when they agree, but state those roles explicitly rather than treating a style reference as exact geometry.

Track source positions and time/state changes separately from fixed structure. Daylight direction, practical lights and local bounce should explain shadows, reflections and subject integration. A designed change in time of day or illumination can change exposure and color while the location's fixed landmarks and layout remain stable. Preserve intentional story-driven lighting changes; do not force the baseline's exposure onto every scene.

## Derive camera views from one place

Supply the selected baseline and relevant original evidence in each independent generation that depends on them. Describe the camera relative to stable landmarks and the designed action axis; change framing, height or lens according to the shot design. World relationships must remain coherent while projected positions and occlusions change. Keeping a landmark at the same screen coordinate across different camera directions does not establish spatial continuity.

When text leaves layout ambiguous, use an available sketch, annotated composition reference, approved blockout or render to provide spatial evidence. This is conditional on the actual tool and model accepting the input. A drawing can guide placement but does not prove exact geometry, dimensions or unseen surfaces. If strict multi-angle geometry requires an unavailable 3D/layout route, report the limitation instead of promising it through prompt wording. Return essential staging or camera-axis changes to the director.

## Combine the selected character and environment

Keep character development and environment development separate until suitable foundations exist. Supply the chosen identity, wardrobe, environment and any required composition references with named purposes. If the environment reference already contains a conflicting person or object, resolve which subject should remain; do not leave the generator to merge two identities. Remove or edit interfering content only through an available authorized route.

Describe integration through relative body/prop scale, ground contact, perspective, shadows, reflections, light direction and material response. The character retains identity and clothing while its illumination changes with the scene. A character asset's neutral background and inspection light are not part of the environment design.

## Handoff

Return real generated image IDs, intended landmarks, layout relationships, light-state distinctions and consuming shots to the coordinator. Mark unseen or invented regions as such. The coordinator reviews continuity and the user selects the location; the generator does not approve a layout or start corrective generations. Preserve unrelated assets and existing scene decisions. A static reference does not establish continuous camera movement or illumination changes.

## Method sources and limits

[Runway's reference workflow](https://help.runwayml.com/hc/en-us/articles/40042718905875-Creating-with-Gen-4-Image-References) demonstrates environment variations and separately developed character/scene paths. Its [advanced reference guidance](https://help.runwayml.com/hc/en-us/articles/41170686463635-Advanced-References-Use-Cases) demonstrate sketch-guided placement and scene staging. Adobe distinguishes [composition references](https://helpx.adobe.com/firefly/web/work-with-images/generate-images/match-image-composition-to-reference-image.html) from [style references](https://helpx.adobe.com/firefly/web/work-with-images/generate-images/reference-images-for-styling.html), and explains [camera-axis continuity](https://www.adobe.com/creativecloud/video/discover/what-is-the-180-degree-rule.html). The baseline, light-state and spatial checks above adapt these practices to production; they do not guarantee scene reconstruction in an arbitrary image model.
