# Shared reference assets

Use for subjects repeated across distinct shots that need consistent identity, or an explicit request for a reference asset. Reusable locations and spatial layouts can also anchor several shots. Read the short [core](../CORE.md) and [image prompt writing](prompt-writing.md) when needed; reuse their current text already in context.

## Decide what is missing

Use the scoped storyboard and available project assets to identify actual consumers, required views and stable attributes. Read missing shot detail or candidate images only where it changes that decision; a direct request for one asset need not inventory the whole film. Titles alone cannot establish suitability.

For each relevant subject, record the consuming shot IDs, reusable image IDs and specific gap. Reuse suitable originals and real existing references; do not regenerate a usable image merely to fill an asset pack. Similar category objects are not automatically the same subject, and planned outfit/state changes are legitimate variants. Multiple frames of one shot do not require a shared asset pack.

Generate only necessary missing views. Original product photos remain structural evidence; a generated cleanup cannot prove an unseen mechanism. Existing suitable images do not need regeneration merely because their background is not white.

## Choose the subject rules

Use [character assets](character-assets.md) for people, [object assets](object-assets.md) for props or products and [scene assets](scene-assets.md) for environments. Their prompt decisions differ; a shared aesthetic does not make skin, cloth, metal and plastic interchangeable materials. Develop character and environment references independently when both are missing, then combine their selected images with explicit subject purposes with explicit scale, support and contact in the prompt.

## Shared aesthetics, asset-specific execution

Use the project's selected look and approved visual references as the asset's aesthetic baseline: medium, realism or stylization, era, palette relationships, material response and finish. Keep the same quality of anatomy, proportion, clothing design and surface treatment expected in the storyboard. Do not independently turn a photographic film into a glossy fashion catalogue, or an illustrated film into photorealistic asset sheets.

Choose presentation for inspection. Show the face and required outfit or the object's silhouette, connections and materials at a useful scale, using a single view or a necessary consistent view sheet. An asset request does not require four temporal panels, internal cut points, dramatic action or the scene's camera path. Simplified backgrounds and legible lighting are aids rather than universal white-background or studio-light requirements. Location assets preserve the chosen environment and useful spatial anchors.

## Reference image design

For isolated subjects, use a simple background and readable light with sufficient margins; a neutral white or gray background is an option, not a required art direction. Preserve a requested background. Show required outfit, footwear and accessories, real product markings and connections. A multi-view or full-body/detail sheet is useful when those views have actual consumers. State panel order, view, shared identity and scale; use labels only where they clarify the reference. No fixed front/side/back pack is required, and a sheet is not automatically a valid single-frame video control.

For a recurring location, retain its environment, light direction, time of day, material appearance and useful landmarks as the shared baseline. An empty location may leave room for later staging; isolate a set piece only when that is the needed asset. A layout sketch can specify relative position, scale and direction when text or generations leave these unstable. The director owns the selected layout; execute it without inventing a different setting. Lock selected identity, outfit and product construction across useful views. Derive additional views from the selected identity image; a front/side/back pack is not automatic.

For photographic characters, apply [character assets](character-assets.md). Choose a readable identity view when the face is unresolved, and a full-body view when clothing or scale is the actual need. Preserve explicit output scope; static, frontal, centered and neutral-backdrop assets are valid. Describe only detail visible at that scale. Reference lighting supports identification without requiring every shadow texture to be visible or dictating downstream scene light.

## Deliver the assigned asset

Return real generated image IDs, intended identity or construction properties, reference uses and unresolved execution limits to the coordinator. Keep pose, background and reference light separate from fixed subject properties. The coordinator owns internal review and the user owns selection; generated candidates are not approved references.

## Asset links and handoff

Create standalone asset tasks with the declared tool contract. Preserve original identity, geometry, outfit, completeness and the selected background. Attach selected real image IDs to consuming shot references when instructed by the user or coordinator, preserving unrelated references. Describe front view, side view or identity as visual uses in purpose or the asset name; do not create a parallel subject/view registry.

Return real assets, intended visual uses, fixed attributes and any unresolved visual dependency. Shared identity references do not replace the artist's composition/state reference for dependent frames. Keep changes to asset work and allowed shot references.
