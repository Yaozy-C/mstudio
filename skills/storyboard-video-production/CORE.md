# Core: media production

Start from the selected shot's current complete text and dialogue, using linked story context where needed. Understand its audience-facing purpose, essential change and narrative result. Ground production in the saved approved design and latest explicit user changes; a coordinator summary or old prompt does not replace them. Preserve the event's meaning when choosing inputs and splitting the scene into single shots.

A clip is a performance, not a slideshow. Preserve the designed action sequence, hierarchy, causes and visible result, the camera's amplitude and speed, the performance as attention and timing, and sound tied to the visible event. Read [motion realism](references/motion-realism.md) when motion drifts, floats, morphs or loses weight.

Inspect relevant material to decide what it supplies, what should vary and which supported route can realize the shot within scope. User-designated generation references must remain actual inputs with their requested purpose; do not replace them with prose, stills or planning-only use. Report concrete incompatibilities before submitting an altered input set. Planning media the user has not required as inputs may be used only for understanding and need not determine final appearance. Explain concrete missing-input needs through the existing handoff, and carry useful observations and production reasons forward when work changes hands.

Preserve the chosen product, characters and scene direction with real references. Use concrete image asset IDs in task references; earlier submitted inputs remain historical evidence, not current truth. Do not turn an ordinary scene into glossy commercial or cinematic imagery without that direction. Preserve physical support, contact and action continuity, and use the selected model's supported parameters.

Video production owns product fidelity through motion and cuts: use the original evidence, preserve visible construction and materials, and repair observed drift within authorization. Execute the director's camera, lens/distance, focus and staging decisions without forcing identical product views. Changes of projection, occlusion and physically motivated deformation are compatible with identity. Return an unsupported essential mechanism or an actual design conflict; do not send ordinary generated component errors back as a request to redesign the shots.

Give every referenced input a concrete purpose that names the subject and the visual use, and keep that assignment stable across segments. `role` is the technical input mode; `purpose` is the visual use.

Create **one video generation task per single continuous shot**. A shot is one camera setup and one continuous action; its `shot.duration` is the intended screen duration. Do not group adjacent shots into one task. If a shot is shorter than the model minimum, generate at the minimum and trim; do not pad, stretch or merge. If a saved shot contains multiple cuts or an internal time map, return it to direction for splitting. A board belongs to one shot; if its panels are different shots, split them before generating. The prompt describes one action and one camera behavior; internal cuts and on-screen text belong to editing.

For a selected shot-board task, the board is a **one-shot state sequence**, not a multi-shot storyboard. Use it as a storyboard reference through a supported reference mode, never as the exact first/last frame. Map its panels to ordered states of the same continuous action; panel boundaries are states, not cuts. If the panels are different editorial shots or planned cuts, stop: split them into separate shot records and separate tasks before generating. Do not ask one model call to execute a four-panel multi-cut board.

Do not request readable on-screen text from the board or the model. Text, subtitles and timecodes belong to editing. A board panel that contains text is a planning reference, not a text-rendering instruction.

An explicitly requested standalone effect or exact-control task keeps its specified format and supported input mode. Do not require a board for it merely because this Skill also handles storyboards. Apply the effect intent, target, protected region, visible progression and ending state from [SKILL.md](SKILL.md) to its actual prompt. These methods do not authorize extra paid inputs, unsupported controls or changes outside the selected effect scope.

Write the complete physical causal chain into the actual prompt, including necessary intermediate contact, support, grip and release states. Preserve structure while allowing physically required pose and deformation changes. Editorial omission requires a designed cut with compatible states; a continuous shot cannot skip a necessary transition. Remove only idle time or repetition that changes no physical state.

Preserve exact required dialogue and voice-over in the actual prompt when the selected video model generates audio, including language, speaker delivery and timing relative to action. A missing standalone audio tool or visible speaker does not remove that capability. Keep subtitle compositing separate from speech generation; captions and empty audio tracks cannot fulfill an audible deliverable. Use a separately selected audio route or report a concrete endpoint limitation without silently dropping speech.

Report actual submission, completion and import states without implying visual approval. Detailed prompt, control and generation rules are listed in [SKILL.md](SKILL.md).
