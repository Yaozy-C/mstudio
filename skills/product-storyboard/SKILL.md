# 全片导演与镜头设计

全片设计时先读当前方案的完整脚本和已有镜头，再确定信息顺序、揭晓、连续动作与可省略过程，以及关键声画衔接。局部修订先读目标镜头、所属段落和相关依据，只有影响连续性或节奏时补读必要相邻镜头，不默认通读或盘点整片。形成判断后保存本次范围内的镜头，不要求把每一步分析变成额外文档或委派。

历史对话和记忆中的其他镜头待办不自动属于本轮范围，也不代表当前已核实状态。局部交付只说明实际修改与相关衔接，不附带无关镜头的待办或修改邀约。

新增读取应解决影响本次设计的具体未知。复用当前上下文已有且未变化的完整结果；目标 ID 使用实际工程返回值，长文按返回偏移补读。工程版本变化时只核实相关对象，不重新盘点全片。空间关系与用户意图已有足够依据时落实并核实修改，返回本次结果及仍影响目标的缺口，不以完善背景为由继续探索。

切镜应有观看、表演、空间或节奏作用；一段可用一镜或多镜，不按字数均分。暂估段落时长可在导演设计中重新分配，说明变化；用户明确锁定的时间不可自行修改。镜头跨段时以主要段落作为 scriptId，其余来源在 text 说明。


## 最高优先级：先忠实于用户意图，再设计创意

从当前消息、工程和原始附件确定任务。区分用户要求、商品事实和探索假设；不编造消费者需求、性能或体验。新创作可以复用商品事实，不自动沿用旧剧情。按 [项目状态](references/project-state.md) 找回当前决定，只改本次范围。

受众、语言、人物是否露脸、风格和禁用创意来自当前项目与用户要求，不设跨项目个人默认值。创意广告按 [创意门槛](references/creative-bar.md) 选择；教程、记录或指定镜头按其目的设计，不强迫视觉奇观。

## 在工程里完成工作

- 脚本由创意编剧使用 ad-script 保存。导演保留已选创意的观看效果、关键事件与用户明确约束；脚本中助手暂拟的距离、角度、完整操作过程和秒数是拍法建议，不自动锁定。实现有冲突时在本职范围内修正拍法，保留吸引用户的视点、揭晓和节奏；只有核心表达需要改变才返回具体问题，不因难生成换成普通展示。
- 已选脚本按 [事实依据](references/brief-and-facts.md)、[观看结构](references/strategy-and-hook.md) 和 [导演设计](references/director-hook.md) 拆镜。shot 关联 planId/scriptId，动作、摄影、观看变化和切口写 text，时长写 shot.duration，台词写 shot.dialogue。
- 依 [镜头与状态](references/shots-and-continuity.md) 逐镜说明来源/初始支撑→动作路径→关键接触→去向；主体和相机分别设计。相邻镜有明确观看作用，不能仅换机位重复同一信息。
- 设计或修正机位、视角和运镜时读 [摄影指导](../creative-ad-director/references/cinematography.md)，先解决同一视点下的可见范围和遮挡，再写精确描述；设计镜内或镜间时间时读 [节奏](../creative-ad-director/references/rhythm.md)。这是当前镜头设计的判断依据，不另加文档、出图或确认步骤。
- 区分时长上限、用户锁定和助手暂拟长度。时间依据动作、辨认与有目的的等待，不按模型片长均分；一镜多格不重复计时。
- 完整图文分镜由镜头拆解与分镜画手协作；按 [预览图](references/preview-images.md) 先检验关键格，再扩展。用户只要文字时止于文字。

## 实际画格与复核

画手按镜头意图准备 shot.framePrompt，实际生成使用 request_generation 的 image 任务；待确认/生成中不等于已有图片。结果完成后用真实 assetId 关联 shot.frames。实际图机位、初始状态或接触关系错误先修，箭头与说明不能补救缺失画面；只凭元数据不能判断画面通过。

镜头拆解对照实际画格检查构图、方向、状态、数量和切口。静帧只能支持静态判断，速度、运动接触和声音须由实际动态证据验证。任务未提供媒体时明确未查。

## 视频生成前的用户审核

沿用当前用户授权和 Mstudio 的任务执行方式，不额外建立审批流程。用户只要方案、分镜或提示词时不生成视频；用户明确要求生成时按指定对象、素材和模型创建任务。若用户明确约定先审核某版方案，遵守该约定；已有同范围授权不重复索要。任务创建、提交、完成和视觉检查分别报告。

制作交接见 [交接格式](assets/production-brief-template.md)，视频由 [视频制作](../product-video-production/SKILL.md) 执行。困难时调整实现路线，不擅自删核心事件。只修改当前权限允许的字段，越权工作通过统筹交适用角色。
