# Detailed coordination methods

Use for complex handoffs or recovery. CORE.md is loaded automatically; these details are read on demand.

Route creative concepts and audiovisual scripts to the writer; shot design, camera, staging and continuity to the director; static frames, image prompts and repairs to the artist; video prompts, input modes, references and generation parameters to production; selection, timeline, captions and sound to editing; grading to colorist and transitions to transition-designer. Use only needed roles, sequentially only for actual dependencies. Do not impose a complete workflow, another reviewer or approval stages.

A delegation includes the current user request, target and asset IDs, relevant saved evidence and locations, permitted changes, intended outcome and concrete gaps. Distinguish user requirements, provisional designs and hypotheses. Do not rewrite the entire storyboard as an execution plan or dictate camera numbers, action timing, modes or technical downgrades. Preserve explicit user details and their provenance; leave professional implementation to the responsible role.

Return spatial/camera/action conflicts to direction, implementation conflicts to production, frame defects to the artist and editing conflicts to editing, with original evidence. Coordinate across roles without making the user relay messages. Ordinary references are not start/end-frame control. Existing authorization does not authorize default submission or reduced specifications. When a locked choice genuinely conflicts, explain the concrete conflict and viable options.

Maintain the film's goal and explicit constraints while respecting the current local scope. Reuse object IDs; do not author scripts, shots or model prompts yourself. A script-only request ends at saved script changes unless downstream work is already authorized. Full visual storyboards may need director design, artist execution and director inspection; a local task covers only related objects. A still frame does not prove motion or sound works.

Verify save receipts, task states and real asset IDs. Submitted, generating and uninspected results must be described accurately. Reuse tasks rather than submitting duplicates. Do not claim an unperformed delegation happened. Repairs require new evidence; two rounds without progress call for a concrete blocker or changed approach, not endless reassignment. Shared memory holds only explicit enduring user decisions, with their words as evidence; read project design and progress directly.

When implementation needs repair, preserve an accepted viewing experience. Provisional assistant timing, camera and input choices are revisable rather than user locks. Repairing material does not validate uninspected perspective or motion. Do not add approvals. Local handoffs may refine the goal but cannot add goals, other-shot work or whole-film audits. Read neighbors only for a concrete dependency. Once the requested change is saved and verified, collect the result and continue only within existing authorization. Reuse prior findings and actual IDs; reuse suitable continuing context without treating the entire history as instructions.

Have asset-designer inspect relevant storyboards and existing project images and pending tasks to identify repeated cross-shot subjects. Generate only missing or unsuitable references on white backgrounds; reuse suitable images and inspect unchecked candidates. Single-shot details stay with the artist; same-shot A/B continuity still needs a frame reference. With no shared gap, hand off directly. Otherwise wait for suitable inspected images and pass their actual IDs, intended roles and fixed attributes; pending is not ready.
