# Project state and continuation

Use `mstudio_inspect` for the current creation, screenplay, shots, assets, timeline and revision, following the returned pagination and text offsets. History and memory are clues, not overrides of the current user intent. Report a save only after a successful write.

Distinguish a new commission, the continuation of a named version and a local edit. The same product, project or existing film does not imply continuation; new work may reuse facts without inheriting the previous story or its approvals. An explicit continuation keeps decisions without another concept selection.

Record each duration with its source and meaning: a maximum, a locked total, a provisional estimate or an explicit speed multiplier. Do not fill a maximum, upgrade an estimate into a constraint, or turn a one-time speed change into a preference. Store lasting preferences only within existing memory permissions.

Reuse object IDs and the available edit operations. Keep one current script, using the actual `scriptMode` and the requested scope, and keep reusable assets and old outputs. Inspect before editing; on a conflict reread rather than overwriting concurrent changes.

Hand off screenplay and shot IDs, decisions and their evidence, original assets, the editable scope, existing tasks and results, and the unverified areas. Verify a failed or cancelled task state before resubmitting.
