# MiniMax H3 prompt adapter

Injected only for the selected MiniMax H3 model. Apply the separately loaded general creative rules first. The structures below organize prompt text, not necessarily API parameters. Verify the current service, mode, input mapping and rewriting behavior; do not assume every host exposes all model capabilities or switch an unknown model to H3.

## Adapt the actual mode

Keep the scene, viewpoint, camera path, action order, light and sound relationships established by general creative guidance. Switching models must not change those decisions. Write direct natural-language shot prose by default; adapt only requirements verified for the selected endpoint. Do not redesign a shot to fill a model template.

| Actual input mode | Input constraint |
|---|---|
| T2VA | No image alignment or invented image references |
| I2VA | The submitted first frame establishes the starting composition/state |
| FL2VA / L2VA | Use frame/ending controls only when exposed by the actual host |
| Full reference | Appearance/composition references are not actual first-frame controls |

The official full-reference document describes **rewrite output**, with subject_definitions, summary, retention_analysis, detailed_description, overall_soundscape and non_diegetic_music. This does not establish that a hosted API requires a six-section user prompt. Do not force those sections or analysis into submitted prompts. If a verified endpoint requires structured text, put the already resolved shot into that structure without changing its meaning. Record host rewriting separately when accessible.

When using H3 reference labels, keep <Subject N>, <Picture N>, <Video N> and <Audio N> traceable to actual inputs; never invent additional assets. Describe each input's role and preserve actual upload order. fully_preserved is a requested constraint, not verified fidelity. Audio copying and timbre/rhythm guidance are different intentions, available only through supported inputs. Preserve the user's requested prompt language unless the endpoint has a verified requirement; always preserve exact dialogue, lyrics and onscreen text.

## Action and cuts

With an actual first frame, describe start, initiation, visible change and result. The frame may already contain ongoing action but must not show an event the prompt asks to perform again. Leave motion space.

Express force through direction, acceleration/deceleration, support changes, contact and material response. Separate camera sentences from subject action; fast tracking cannot substitute for subject acceleration. H3 may use multiple shots; do not impose one action per call. Validate difficult relationships with the minimum useful segment, not unrelated added actions or impossible timing.

When using H3 shot labels, [Shot 1] has no cut timestamp; subsequent shots use [Shot N] At MM:SS.mmm, ... with increasing times within the clip. Timing still requires output inspection. Do not assume all models ban negative wording or that a negative_prompt API field exists. Prefer concrete desired states and pass exclusions through supported controls.

## Sound

Write synchronized contact sound at the corresponding event in the main description: objects/materials, onset and decay. In optional structured text, overall_soundscape summarizes ambience, physical sound and nonverbal voices in a short English paragraph; do not duplicate dialogue or singing there. Use N/A only when silence is explicitly required throughout.

If using structured sound sections, use non_diegetic_music: N/A when no score is needed; otherwise specify instruments, tempo, rhythm and dynamics. These fields neither guarantee exact sync nor operate an API mute switch. Follow the selected plan for separate audio production.

## Example: contact and release

This is an untested illustration, not a default story. The actual first frame must precede the cup's contact with the table.

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.

integrated_multimodal_description: [Shot 1] Live-action, a close shot starts from the hand, ceramic cup and wooden table shown in <Picture 1>. The hand lowers the cup in one decisive movement. The cup base meets the wooden surface with one short, dry tap, then the fingers release the handle. The camera holds a static shot through the contact and release. The cup retains its shape and surface pattern.

overall_soundscape: A quiet indoor room tone underlies a single dry ceramic-on-wood tap at contact and faint sleeve rustle as the hand withdraws.

non_diegetic_music: N/A
```

Do not turn decisive placement into throwing; sound follows actual contact.

## Diagnose and hand off

Record version, actual mode/endpoint, input order/roles, final text, clip duration, selected range and action/sound failure conditions. Record accessible prompt rewriting; otherwise mark it unknown.

Floating action calls for checking the start/path and speed change. Contact failure calls for reference/control repair, not louder sound or global speed. Repeated diagnosed failure follows current retry limits and route changes. Valid action with long waits calls for trimming. Valid imagery with faulty audio should retain the image and repair sound where possible; a mixed track may need reconstruction rather than claimed lossless separation.

Observe product parts, path/force, camera, sound material and sync separately. Without playback/listening, leave the corresponding result unverified.

## Source status

Official base and reference guides document rewrite syntax, not a universal hosted API submission contract; Mstudio has no network access, so work from this injected guidance and the current host capabilities rather than fetching them. Community suggestions about forcing speed through extra actions or synonyms are conflicting anecdotes, not hard rules.
